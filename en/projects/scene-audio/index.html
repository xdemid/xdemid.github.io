Unity tool In development

Scene Audio

Sound events, banks and bindings routed within a Unity scene.

Role

Personal tool; detailed authorship has not been documented yet.

Technologies / disciplines

Unity / Audio / Editor tools

Personal contribution

An independent module, feature description and validation of existing tests have been prepared.

Current state

Source and EditMode tests verified; a public package and player build are still pending.

From an event to a sound

Scene Audio binds component events to stable Sound IDs and SoundBank clips. Events are declared using AudioEventSource/AudioEvent metadata and emitted through AudioEvents.Emit or AudioEventEmitter. Bindings support variants, pitch/volume, avoidance of immediate repeats and minimum intervals.

An enabled AudioManager is selected in the source component’s scene. If several managers exist in one scene, the last registered one wins; the intended workflow uses one manager per scene.

Authoring and preview

Tools → Audio → Scene Audio Events discovers sources and provides binding, manager, audio source and preview controls. Create a SoundBank through Assets → Create → PlayWorks → Audio → Sound Bank. Samples include the Audio scene, a demo bank and the Ping clip.

The complete SceneAudio folder with .meta files installs independently. PSM, SceneAudit, SplineProgress and Luna are not required. The Sound ID generator locates its module folder dynamically.

Storage and runtime boundaries

Play Mode drafts and reports live in Library/SceneAudio: clearing Library removes pending drafts. Temporary pitched WAV previews use Assets/__SceneAudioPreview. Preview depends on the internal AudioUtil API and may be unavailable on another Unity version.

MasterVolume acts through the global AudioListener. Mute until first interaction uses legacy input and requires legacy input or Both. Additive-scene games must coordinate global volume separately from scene-local routing.

Validation and media

Six EditMode tests passed in a separate Unity 6000.6.0f1 project, covering bank caches, serialization, scene routing, portable editor paths and layout. Sound quality and player builds have not been verified. The cover is a labelled graphic placeholder; actual footage, an audio demonstration and a download are pending.

Other tools: Scene Audit, Playable State Machine and Spline Progress.
